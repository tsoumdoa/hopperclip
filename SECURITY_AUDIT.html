Executive summary

No Critical issues were found. Detail

#1 High

No HTTP security response headers configured anywhere

vite.config.ts · src/start.ts:4-12 · src/routes/__root.tsx:33-58 · (no vercel.json)

Impact
No CSP means any injected markup or compromised dependency has no browser-enforced ceiling. Missing X-Frame-Options/frame-ancestors permits clickjacking. Missing HSTS allows SSL-strip on first visit. Missing Referrer-Policy can leak full URLs (including ?token=… share tokens) to third parties (Google Fonts, PostHog).
Fix
Add a Nitro routeRules block in vite.config.ts (or a vercel.json headers array). Minimum baseline: CSP scoped to 'self' + Clerk/Convex/PostHog/Fonts origins, Strict-Transport-Security, X-Content-Type-Options: nosniff, Referrer-Policy: strict-origin-when-cross-origin, frame-ancestors 'none'. Highest single-item impact in this report — also constrains findings #3 and the font-SRI note.
#2 Medium

Revoking a share does not invalidate presigned R2 URLs

convex/ghPublicAction.ts:30-39

Scenario
The share flow signs an R2 GET URL with aws4fetch using no explicit expiresIn, so the URL defaults to R2's max window (up to 7 days). When the owner clicks Revoke (revokeShare), the shares row is deleted and /share?token=… stops working — but a recipient who already obtained the presigned URL can keep downloading the file for the full default window. The URL can also leak into logs / history / Referer.
Fix
Set an explicit short TTL (5–15 min) on the presigned URL and re-request on demand, or pass X-Amz-Expires. Also consider rotating the object key on revoke.
#3 Medium

PostHog captures exceptions; token may leak via Referer

src/app/providers/PostHogProvider.tsx:16-18

Impact
capture_exceptions: true sends stack traces (and any serialized locals) to the PostHog US cloud. capture_pageleave: true + no Referrer-Policy means the /share?token=… query string can leak to third-party origins. Inputs are already masked in session replay (maskAllInputs: true) — good.
Fix
Add a before_send scrubber that strips URL search params / token fields before events leave the browser. Pair with Referrer-Policy: strict-origin-when-cross-origin from finding #1. Consider capture_exceptions: false if stack-trace egress is unacceptable.

#5 Medium

Server-side tag validation weaker than client

convex/ghCard.ts:13-23 · convex/schema.ts:13 · src/types/types.ts:10-13

Scenario
The shared GhCardSchema validates tag count (max(20)) but applies no per-element length or character restriction; Convex schema is even looser (v.array(v.string())). The frontend enforces ≤20 chars and alphanumeric-only, but that is trivially bypassed by calling api.ghCard.addPost directly. An attacker stores near-1-MB tag payloads that then amplify cost through getUserTags (flatMap/reduce over all posts).
Fix
Tighten the server schema: z.array(z.string().min(1).max(20)).max(20). Apply the same constraint in convex/schema.ts if DB-layer enforcement is desired.
#6 Medium

XSS defense-in-depth: Shiki output via dangerouslySetInnerHTML

src/app/duckerweb/components/GHScriptNode.tsx:120-124 · src/app/duckerweb/components/GHJsonView.tsx:38-43

Impact
Both components feed attacker-controlled strings (GH source / JSON.stringify(parsedGrasshopper)) into highlighter.codeToHtml(...) and inject the result with dangerouslySetInnerHTML. Not currently exploitable — Shiki HTML-escapes tokens, and the fallback branch escapes &/</>. But this is single-vendor reliance on a third-party highlighter; a Shiki regression or refactor of the fallback path would turn a shared GH file into stored XSS in every viewer who opens the share link.
Fix
Add DOMPurify.sanitize around Shiki output before injection, or switch to Shiki's codeToTokens + React renderer and drop dangerouslySetInnerHTML. At minimum, also escape " and ' in the fallback to harden against future refactors.
#7 Low

Share-token entropy ~52 bits; no rate limiting

src/utils/generage-shareable-link-uid.ts:1-12 · convex/ghPublicAction.ts:13

Impact
customAlphabet(..., 10) yields 36¹⁰ ≈ 2⁵¹·⁷. The token is the sole bearer secret protecting both metadata (getSharedPost) and the presigned file URL (generateShareableLink) — both reachable unauthenticated with no throttling. Below the 128-bit recommendation for bearer secrets; a distributed attacker could probe.
Fix
Lengthen to ≥21 chars (≥122 bits) and update ShareLinkUidSchema. Add Convex rate limiting (per-IP / fingerprint) on the public share actions.
#8 Low

CLERK_JWT_ISSUER_DOMAIN referenced but undefined

convex/auth.config.ts:6

Impact
process.env.CLERK_JWT_ISSUER_DOMAIN! uses a non-null assertion but the variable is absent from .env, .env.local, and env.example. Convex auth config silently receives domain: undefined, which can cause JWT verification to behave unexpectedly. (JWT_PRIVATE_KEY / JWT_PUBLIC_KEY are likewise defined but unreferenced in tracked app code.)
Fix
Wire CLERK_JWT_ISSUER_DOMAIN into the env files + env.example, or remove the non-null assertion and the dead JWT_* keys. Document which component consumes the RSA keys.
#9 Low

Share token carried in URL query string

src/app/components/gh-card-dialog.tsx:118 · src/routes/share.tsx:18

Impact
Standard for share links, but the bearer secret in ?token=… leaks via browser history, shared-device history, proxy/server access logs, and the Referer header (the page loads Google Fonts and PostHog).
Fix
Prefer a path segment (/share/<token>) plus Referrer-Policy: no-referrer on the share page, and ensure no third-party requests fire while the token is in the URL.
#10 Low

Missing share-cleanup cron job

convex/ghCard.ts:435 (no cron.ts / scheduled fn)

Impact
The comment states cleanup "will be handled by scheduled job," but no cron/scheduled function exists in convex/. Read-time expiry checks are correct (getSharedPost, getShareableLink), so this is operational rather than a bypass: stale shares rows accumulate, extending the window in which a leaked presigned URL pairs with a still-present object key (compounds finding #2).
Fix
Add a daily Convex cron job that deletes shares rows where expiryDate < now using the existing by_expiryDate index.
#11 Low

Parser record keys from attacker-controlled XML

parser/src/parser.ts:46-49,395-397,419-421,534-535

Impact
Several record builds use attacker-controlled name/NickName as object keys without sanitizing. Not global prototype pollution — each assignment is single-level against a fresh {}, so the blast radius is one malformed node, not Object.prototype. Still worth hardening against future refactors that might introduce recursive merging.
Fix
Build these maps with Object.create(null), or reject keys in { "__proto__", "constructor", "prototype" }.
#12 Low

forceRedirectUrl echoes full current URL

src/routes/_authed.tsx:18

Impact
forceRedirectUrl={window.location.href} echoes any query/hash an attacker appends to the URL a victim clicks before the sign-in bounce. Classic open-redirect shape, but Clerk validates redirect URLs against the dashboard allow-list — exploitability depends entirely on that config.
Fix
Prefer a fixed target (forceRedirectUrl="/ghcards") rather than echoing the full current URL.
#13 Low

sortOrder weakly validated

convex/ghCard.ts:154-157

Impact
v.optional(v.string()) then cast to SortOrder. There is a default branch, so this is not exploitable — but SortOrderZenum already exists in the codebase and is never used here, so the validation is inconsistent with intent.

Verified secure 11 areas

These "usual suspects" were checked carefully and found correctly protected.

  • No IDOR. Every doc-id-bearing Convex function fetches the document and verifies post.clerkUserId === identity.id before acting (convex/ghCard.ts).
  • No XXE / billion-laughs. fast-xml-parser@^5.9.3 is non-validating and ignores DTDs/entities by design. No other XML parser in the bundle.
  • Decompression bombs mitigated. Streaming size caps on gzip (100 MB) and raw-DEFLATE paths; 25 MiB compressed upload cap enforced server- and client-side.
  • Binary parser is defensive. Recursion depth cap (128), bounds checks on every read, negative-length rejection, 7-bit-int overflow guards, SizeBoundedWriter.
  • No eval/new Function/child_process anywhere in src/ or parser/.
  • Stored XSS via Panel/Scribble text rendered as JSX children (auto-escaped) — not via dangerouslySetInnerHTML.
  • No path traversal. Storage keys are server-generated nanoid() validated against /^[A-Za-z0-9_-]{1,64}$/; R2 key built as ${R2_URL}/${userId}/${storageKey}.
  • No ReDoS. Hand-written regexes use bounded [^>] classes; no catastrophic backtracking.
  • No secrets committed. Verified across all refs incl. t3/checkpoints via git log --all -S; .gitignore covers .env*, *.tsbuildinfo, .output/.
  • CSRF middleware applied to all server functions (src/start.ts:5); Clerk JWTs cryptographically verified by Convex (convex/auth.config.ts).
  • No source maps shipped; no server secrets in client bundle (src/env.ts server/client split).
