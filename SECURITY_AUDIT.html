Executive summary

No Critical issues were found. The codebase is notably well-defended for its attack surface: every Convex mutation/query enforces authentication and per-user ownership (no IDOR), the XML parser is XXE-proof by library design, decompression-bomb limits are applied at every layer, no secrets are committed, and the client/server environment split is clean.

The headline gap at audit time — a complete absence of HTTP security response headers — has since been remediated: vite.config.ts now sets CSP, HSTS, frame-ancestors 'none', Referrer-Policy, X-Content-Type-Options, and Permissions-Policy on every Nitro route (finding #1 / PR 1). The residual CSP gap is script-src 'unsafe-inline', kept in production because TanStack Start streams inline hydration scripts and four routes are prerendered to static HTML (per-request nonces cannot match build-time markup; Clerk also requires it without strict-dynamic); 'unsafe-eval' is dev-only. Remaining Medium items are share-download TTL after revoke (#2), analytics scrubbing (#3), and server tag validation (#5). Everything else is Low / Informational hardening.

Detail

#1 Fixed

HTTP security response headers — remediated via Nitro routeRules

vite.config.ts:16-52 (buildSecurityHeaders) · applied to /** via the nitro() plugin

Original impact (pre-remediation)
No CSP meant any injected markup or compromised dependency had no browser-enforced ceiling; missing frame-ancestors permitted clickjacking; missing HSTS allowed SSL-strip on first visit; missing Referrer-Policy could leak ?token=… share URLs to third parties.
Configured now
CSP with default-src 'self', object-src 'none', frame-ancestors 'none', base-uri 'self', form-action 'self', script/style/connect/frame sources scoped to Clerk, Convex, PostHog, Cloudflare Turnstile, Google Fonts, and the exact R2 bucket origin, plus upgrade-insecure-requests in production builds. Companion headers: Strict-Transport-Security (1y, includeSubDomains, preload), X-Content-Type-Options: nosniff, X-Frame-Options: DENY, Referrer-Policy: strict-origin-when-cross-origin, Permissions-Policy (camera/mic/geolocation denied), Cross-Origin-Opener-Policy: same-origin. Production builds fail unless R2_URL is set, so connect-src pins the exact bucket origin rather than a *.r2.cloudflarestorage.com wildcard.
Residual risk
script-src retains 'unsafe-inline' in production: TanStack Start streams inline hydration scripts, and four routes are prerendered to static HTML, so a per-request nonce can never match build-time markup (Clerk likewise requires it without a strict-dynamic setup). Inline-script injection is therefore not blocked by CSP; compensating controls are React/JSX auto-escaping (see “Verified secure”) and the object-src/base-uri/form-action lockdown. 'unsafe-eval' is emitted only for the Vite dev server. Revisit nonces if prerendering is dropped or an edge HTML-rewrite layer is added.
#2 Medium

Revoking a share does not invalidate presigned R2 URLs

convex/ghPublicAction.ts:30-39

Scenario
The share flow signs an R2 GET URL with aws4fetch without setting X-Amz-Expires. The library then defaults to X-Amz-Expires: 86400 (24 hours) for S3/R2 query signing — verified at aws4fetch@1.0.20 source lines 122-123 (R2 URLs resolve to service='s3', triggering the default) — not R2's 7-day maximum. When the owner clicks Revoke (revokeShare), the shares row is deleted and /share?token=… stops working — but a recipient who already obtained the presigned URL can keep downloading the file for the remaining TTL. The URL can also leak into logs / history / Referer.
Fix
Set an explicit short TTL (5–15 min) via X-Amz-Expires on the signed request and re-request on demand. Optionally rotate the object key on revoke for hard invalidation.
#3 Medium

PostHog captures exceptions; token may leak via Referer

src/app/providers/PostHogProvider.tsx:16-18

Impact
Two related but separable issues: (1) capture_exceptions: true sends stack traces (and any serialized locals) to the PostHog US cloud; (2) without Referrer-Policy, /share?token=… can leak on third-party requests (Fonts, PostHog). Session replay already masks inputs (maskAllInputs: true) — good. Item (2) is largely fixed by finding #1; keep a scrubber for (1).
Fix
Add a before_send scrubber that strips URL search params / token fields before events leave the browser. Pair with Referrer-Policy from finding #1. Consider capture_exceptions: false if stack-trace egress is unacceptable.

#5 Medium

Shared Zod tag schema validates count only

src/types/types.ts:12 · convex/schema.ts:13 · src/app/hooks/use-validate-name-and-description.ts:31-66

Scenario
addPost/updatePost already run GhCardSchema.parse, which caps tag count at 20 but applies no per-element length or charset. The UI enforces ≤20 chars and \p{L}\p{N} (Unicode letters/numbers — not ASCII alphanumeric-only), but that is bypassable by calling the mutation directly. Convex DB schema is looser still (v.array(v.string())). An attacker can store oversized tag strings that amplify cost through getUserTags.
Fix
Tighten the shared schema: z.array(z.string().min(1).max(20).regex(/^[\p{L}\p{N}]+$/u)).max(20) (or equivalent). Optionally mirror in convex/schema.ts if DB-layer enforcement is desired.
#6 Low

Defense-in-depth: Shiki output via dangerouslySetInnerHTML

src/app/duckerweb/components/GHScriptNode.tsx:120-124 · src/app/duckerweb/components/GHJsonView.tsx:38-43

Impact
Both components feed attacker-controlled strings (GH source / JSON.stringify(parsedGrasshopper)) into highlighter.codeToHtml(...) and inject the result with dangerouslySetInnerHTML. Not currently exploitable — Shiki HTML-escapes tokens, and the fallback branch escapes &/</>. Rated Low as single-vendor reliance: a Shiki regression or fallback refactor could turn a shared GH file into stored XSS.
Fix
Add DOMPurify.sanitize around Shiki output before injection, or switch to Shiki's codeToTokens + React renderer and drop dangerouslySetInnerHTML. At minimum, also escape " and ' in the fallback to harden against future refactors.
#7 Low

Share-token entropy ~52 bits; no rate limiting

src/utils/generage-shareable-link-uid.ts:1-12 · convex/ghPublicAction.ts:13

Impact
customAlphabet(..., 10) yields 36¹⁰ ≈ 2⁵¹·⁷. The token is the sole bearer secret protecting both metadata (getSharedPost) and the presigned file URL (generateShareableLink) — both reachable unauthenticated with no throttling. Below the 128-bit recommendation for bearer secrets; a distributed attacker could probe.
Fix
Lengthen to ≥21 chars (≥122 bits) and update ShareLinkUidSchema. Add Convex rate limiting (per-IP / fingerprint) on the public share actions.
#8 Low

CLERK_JWT_ISSUER_DOMAIN undocumented; unsafe ! assertion

convex/auth.config.ts:6 · env.example

Impact
process.env.CLERK_JWT_ISSUER_DOMAIN! uses a non-null assertion, and the variable is absent from env.example / local .env* templates. In production this is typically set as a Convex dashboard env var — absence from the repo does not mean live auth receives domain: undefined. The real gaps are: onboarding docs omit a required Convex env, and a failed local/misconfigured deploy fails opaquely. Unused local JWT_PRIVATE_KEY / JWT_PUBLIC_KEY (if present only in ignored .env) are hygiene, not committed secrets.
Fix
Document CLERK_JWT_ISSUER_DOMAIN in env.example / README as a Convex dashboard variable. Prefer failing fast when unset over !. Remove unused JWT_* keys from local env if nothing consumes them.
#9 Low

Share token carried in URL query string

src/app/components/gh-card-dialog.tsx:118 · src/routes/share.tsx:18

Impact
Standard for share links, but the bearer secret in ?token=… leaks via browser history, shared-device history, some proxy/server access logs, and the Referer header (the page loads Google Fonts and PostHog). Moving to a path segment (/share/<token>) does not stop Referer leakage — the path is still sent — though some access logs strip query strings only.
Fix
Primary: ship Referrer-Policy from finding #1 (prefer no-referrer or strict-origin-when-cross-origin on the share page) and scrub analytics (#3). Optional: path-segment URL for cleaner links / log hygiene, not as a Referer fix.
#10 Low

Missing share-cleanup cron job

convex/ghCard.ts:435 (no cron.ts / scheduled fn)

Impact
The comment states cleanup "will be handled by scheduled job," but no cron/scheduled function exists in convex/. Read-time expiry checks are correct (getSharedPost, getShareableLink), so this is operational rather than a bypass: stale shares rows accumulate, extending the window in which a leaked presigned URL pairs with a still-present object key (compounds finding #2).
Fix
Add a daily Convex cron job that deletes shares rows where expiryDate < now using the existing by_expiryDate index.
#11 Low

Parser record keys from attacker-controlled XML

parser/src/parser.ts:87,97,102,108

Impact
Several record builds use attacker-controlled name (from item.Name) as object keys (result[name] = { }) without sanitizing. Not global prototype pollution — each assignment is single-level against a fresh {}, so the blast radius is one malformed node, not Object.prototype. Still worth hardening against future refactors that might introduce recursive merging.
Fix
Build these maps with Object.create(null), or reject keys in { "__proto__", "constructor", "prototype" }.
#12 Low

src/routes/_authed.tsx:18

Impact

Verified secure 11 areas

These "usual suspects" were checked carefully and found correctly protected.

  • No IDOR. Every doc-id-bearing Convex function fetches the document and throws unless post.clerkUserId === identity.id (throw-on-mismatch form: if (post.clerkUserId !== identity.id) throw) before acting (convex/ghCard.ts).
  • No XXE / billion-laughs. fast-xml-parser@^5.9.3 is non-validating and ignores DTDs/entities by design. No other XML parser in the bundle.
  • Decompression bombs mitigated. Streaming size caps on gzip (100 MB) and raw-DEFLATE paths; 25 MiB compressed upload cap enforced server- and client-side.
  • Binary parser is defensive. Recursion depth cap (128), bounds checks on every read, negative-length rejection, 7-bit-int overflow guards, SizeBoundedWriter.
  • No eval/new Function/child_process anywhere in src/ or parser/.
  • Stored XSS via Panel/Scribble text rendered as JSX children (auto-escaped) — not via dangerouslySetInnerHTML.
  • No path traversal. Storage keys are server-generated nanoid() validated against /^[A-Za-z0-9_-]{1,64}$/; R2 key built as ${R2_URL}/${userId}/${storageKey}.
  • No ReDoS. Hand-written regexes use bounded [^>] classes; no catastrophic backtracking.
  • No secrets committed. Verified across all refs incl. t3/checkpoints via git log --all -S; .gitignore covers .env*, *.tsbuildinfo, .output/.
  • CSRF middleware applied to all server functions (src/start.ts:5); Clerk JWTs cryptographically verified by Convex (convex/auth.config.ts).
  • No source maps shipped; no server secrets in client bundle (src/env.ts server/client split).
